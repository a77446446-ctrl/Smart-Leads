# Проверка бонуса, диагностика прокси и сохранение парсера

## Окончательное решение владельца

14.09.2026 владелец уточнил: настройки подключения аккаунта и логика парсера должны остаться как в исходной рабочей копии. Добавленная ранее проверка `categoryMatched` в `max-parser.ts` отменена. Все 12 защищённых файлов снова совпадают с исходным `source-integrity.json` побайтно. Исключений из проверки целостности нет.

Исходный режим «Целевые» проверяет качество, даты, контакты, антиспам и оценку сообщения. Отсутствие совпадения категории само по себе не запрещает сохранение в «Другое». Строгий отбор по категориям в этой версии намеренно не добавляется. Старый тест требовал именно такого изменения поведения, поэтому заменён проверкой исходной целостности. Дополнительно настоящая обработка проверяется на совпадении/отсутствии категории, минус-словах категории, выключенных категориях, контактах, антиспаме, оценке и дубликатах. Режим «Все» сохраняет исходный текст даже при недоступности анализа.

## Приветственный бонус

Код авторизации и начисления не изменён. Тест больше не зависит от имени переменной: вызывается настоящий обработчик MAX с подписанными тестовыми данными, проверяются баланс, отметка начисления и запись журнала. Проверяются повторные входы, выключенный бонус, выключенная монетизация и нулевая сумма.

`npm run test:bonus:postgres` проверяет восемь одновременных входов на настоящей локальной PostgreSQL. Результат — один пользователь, одно начисление 450 рублей, одна операция. Искусственная ошибка вставки в журнал откатывает создание второго тестового пользователя и начисление. Тест создаёт уникальную схему с копиями структуры четырёх таблиц и удаляет только её в `finally`; рабочие записи не меняются. Тест намеренно разрешён только для локальной базы `smart_leads_local` и требует уже применённых миграций.

## Интерфейс прокси

На странице `/admin/settings` в режиме прокси постоянно видны две кнопки:

- «Проверить прокси» — существующая быстрая проверка, без запуска QR-входа.
- «Диагностика прокси (пошаговая)» — существующая диагностика DNS, TCP и подключения через выбранный протокол; результат выводится в журнал событий.

Пустые IP/порт блокируют кнопки; неверный порт вызывает понятную ошибку. Во время проверки поля и повторные действия заблокированы. Пошаговая диагностика ограничена временем ожидания на клиенте. Авторизация продолжает использовать прежний обработчик и прежние скрипты. Проверка сохраняет введённый прокси в существующий зашифрованный черновик, как это уже делалось при добавлении аккаунта.

Установлены локальные `.venv`, зависимости из `requirements-parser.txt` и Chromium версии, требуемой Playwright. В `.env.local` указан `PARSER_PYTHON_EXECUTABLE=".venv/Scripts/python.exe"`. Эти файлы локального окружения не должны попадать в клиентскую поставку.

`npm run test:proxy:local` выполняет настоящие обработчики и Python-скрипты на локальных эмуляторах HTTP/SOCKS5. Проверены успешное соединение, отказ прокси и отказ доступа 401/403. Эмуляторы не обращаются в MAX и не используют реальные реквизиты. Проверка конкретного прокси пользователя и вход его MAX-аккаунта остаются пользовательской приёмкой.

В браузере подтверждены видимость обеих кнопок, доступность после заполнения полей и вывод ошибки в журнал без запуска QR-входа. Временные значения из формы убраны; сохранённый прокси не создавался.
