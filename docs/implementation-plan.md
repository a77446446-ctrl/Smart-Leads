Как будем реализовывать Smart Leads
Этап 1. Сохраняем рабочую систему
Текущий проект «По делам» остаётся отдельным эталоном и продолжает работать как раньше.
Smart Leads развивается отдельно:
По делам              Smart Leads
рабочая система       коммерческая версия
свои данные            нейтральные настройки
свои секреты           секреты клиента
свой бренд             настраиваемый бренд
Файл scripts/parser_worker.py не изменяем. Также не затрагиваем проверенную цепочку публикации лидов в MAX.
Этап 2. Создаём чистую основу
Из архива подготавливается рабочая папка с коротким путём, например:
D:\Smart-Leads
В чистой версии остаются:
- src;
- scripts;
- prisma;
- public;
- docs;
- package.json;
- package-lock.json;
- Dockerfile;
- requirements.txt;
- .env.example;
- конфигурационные файлы.
В рабочую коммерческую копию не переносятся реальные:
- .env;
- базы данных;
- MAX-сессии;
- резервные копии;
- лиды;
- телефоны;
- логи;
- отладочные материалы.
Папки node_modules, .next и .venv можно будет создать заново командой установки зависимостей.
Этап 3. Проводим аудит проекта
Составляется карта приложения:
- страницы;
- API-маршруты;
- модели базы;
- авторизация;
- настройки;
- MAX-парсер;
- доставка лидов;
- платежи;
- роли пользователей;
- места, где зашито название «По делам»;
- места, где используются конкретные данные вашего проекта.
Результатом будет список:
- что уже готово;
- что нужно изменить;
- что нельзя менять;
- какие функции можно вынести в настройки;
- какие функции требуют новых таблиц или маршрутов.
Этап 4. Делаем нейтральный бренд
Название Smart Leads, логотип, цвета и тексты выносятся из компонентов в настройки.
В дальнейшем конкретный клиент сможет задать:
- название продукта;
- логотип;
- цветовую схему;
- описание;
- название бота;
- контакты поддержки;
- приветственный текст;
- название категорий.
Один и тот же код сможет работать под названиями «Новости дня», «СтройЛид», «МедиаМонитор» или любым другим брендом.
Этап 5. Разделяем роли
В приложении будут отдельные уровни доступа.
Владелец коммерческого экземпляра:
- подключает MAX;
- указывает токены;
- добавляет источники;
- настраивает категории;
- подключает Telegram;
- управляет пользователями;
- меняет бренд.
Обычный пользователь:
- входит в приложение;
- читает новости или лиды;
- использует поиск и категории;
- получает уведомления;
- открывает доступные материалы;
- не видит токены, источники и настройки парсинга.
Технический администратор:
- занимается сервером;
- Coolify;
- базой данных;
- доменом;
- обновлениями;
- резервными копиями;
- восстановлением.
Этап 6. Добавляем вход через MAX и Telegram
Вход через MAX сохраняется.
Добавляется вход через Telegram:
- клиент подключает своего Telegram-бота;
- домен регистрируется в BotFather;
- сервер проверяет данные авторизации;
- Telegram-пользователь связывается с учётной записью приложения;
- права доступа назначаются внутри Smart Leads.
Telegram поддерживает официальный Login/OIDC-процесс с проверкой токена на сервере и заранее зарегистрированными URL. (официальная документация Telegram Login)
Этап 7. Добавляем Telegram как второй канал доставки
MAX остаётся источником парсинга и основным каналом.
Telegram становится дополнительным каналом:
MAX-аккаунт клиента
        ↓
   парсинг MAX
        ↓
 единая заявка или новость
   ↙        ↓        ↘
сайт      MAX-бот   Telegram-бот
Клиент сможет:
- подключить Telegram-бота;
- указать группу или канал;
- выбрать категории для публикации;
- включить или отключить отправку;
- получать новости одновременно в MAX и Telegram.
Telegram Bot API поддерживает вебхуки и отправку сообщений, фотографий, видео, аудио и документов. (официальная документация Telegram Bot API)
Для Telegram будет отдельная очередь доставки. Если Telegram временно недоступен, MAX и сам парсер продолжат работать.
Этап 8. Добавляем изображения, видео и аудио
Каждое сообщение будет храниться как материал:
- текст;
- заголовок;
- источник;
- дата;
- категория;
- изображения;
- видео;
- аудио;
- документы;
- подпись;
- ссылка на источник.
Материалы можно будет:
- показывать в веб-приложении;
- отправлять в MAX;
- отправлять в Telegram;
- хранить в архиве.
На этапе аудита нужно проверить, что текущий MAX-парсер уже получает данные о вложениях. Если он передаёт ссылки или идентификаторы медиа, обработку можно добавить вокруг него.
Если текущий parser_worker.py получает только текст, полноценное извлечение медиа потребует изменения защищённой логики extract_messages. На это понадобится ваше отдельное разрешение. Без него файл останется неизменным.
Также потребуется учитывать:
- размер файлов;
- недоступные вложения;
- защищённые сообщения;
- временные ссылки;
- повторную загрузку;
- удаление старых медиа;
- права на повторную публикацию материалов из чужих чатов.
Этап 9. Создаём мастер подключения клиента
Клиент проходит пошаговую настройку:
1. Задаёт название и логотип.
2. Указывает MAX ID администратора.
3. Вводит токен MAX-бота.
4. Авторизует аккаунт MAX для парсинга.
5. Добавляет чаты.
6. Создаёт категории.
7. Настраивает ключевые и исключающие слова.
8. Подключает Telegram-бота.
9. Выбирает Telegram-канал или группу.
10. Проверяет тестовую отправку.
11. Приглашает обычных пользователей.
Приложение должно показывать понятные статусы: «подключено», «требуется действие», «ошибка доступа», «бот не добавлен в канал».
Этап 10. Готовим развёртывание через VPS и Coolify
Для каждого клиента создаётся отдельный экземпляр:
- отдельный VPS или изолированный проект;
- отдельная база PostgreSQL;
- отдельный домен;
- отдельные секреты;
- отдельные MAX-сессии;
- отдельные Telegram-боты;
- отдельные резервные копии.
В Coolify подставляются технические параметры клиента. Сам клиент получает готовый интерфейс и не работает с базой или сервером.
Подготавливаются:
- шаблон переменных окружения;
- инструкция установки;
- проверка HTTPS;
- health check;
- резервное копирование;
- обновление;
- восстановление;
- диагностика.
Этап 11. Создаём демо-режим
Для продаж нужен отдельный демонстрационный экземпляр:
- тестовый бренд;
- вымышленные новости;
- демонстрационные изображения;
- безопасный MAX-бот;
- безопасный Telegram-канал;
- ограниченные права;
- автоматический сброс тестовых данных.
Клиент сможет посмотреть продукт до покупки, не получая доступ к вашим рабочим данным.
Этап 12. Готовим рекламную упаковку
После технической основы создаются:
- посадочная страница;
- презентация на 6–8 слайдов;
- PDF-инструкция;
- сценарий двухминутного видео;
- текст коммерческого предложения;
- тарифы;
- форма заявки;
- список вопросов для клиента;
- скрипт демонстрации;
- шаблон договора;
- лицензионные условия;
- инструкция подключения.
Этап 13. Проводим проверку
Развёртывание проверяется с чистого листа:
- новый домен;
- новая база;
- новый MAX-бот;
- новый Telegram-бот;
- новый аккаунт администратора;
- новые чаты;
- новые категории;
- тестовые изображения;
- тестовое видео;
- тестовое аудио;
- доставка в веб-приложение;
- доставка в MAX;
- доставка в Telegram;
- права обычного пользователя;
- резервное копирование;
- восстановление;
- обновление.
После изменений выполняются обязательные проверки:
npm test
npm run typecheck
npm run build
Также отдельно проверяется, что scripts/parser_worker.py остался без изменений.
