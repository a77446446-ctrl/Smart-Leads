# Развертывание этапа 0 в Coolify

## Параметры приложения

- Версия Node.js: `22.x`.
- Команда сборки: `npm ci && npm run build`.
- Команда запуска: `npm run start`.
- Проверка перед развертыванием: `npm run verify && npm test`.

`npm run start` одновременно запускает Next.js и внутренний планировщик парсера. Планировщик обращается только к локальному HTTP-интерфейсу приложения и подписывает запросы секретом `CRON_SECRET`.

## Обязательные переменные окружения

Скопируйте названия из `.env.example`, но не переносите тестовые значения и реальные секреты в Git.

- `DATABASE_URL` — строка подключения приложения к PostgreSQL.
- `DIRECT_URL` — прямое подключение для миграций Prisma.
- `CRON_SECRET` — случайная строка длиной не менее 32 байт.
- `NEXT_PUBLIC_APP_URL` — постоянный публичный HTTPS-адрес приложения без завершающего `/`.

Переменные MAX, авторизации и ЮKassa станут обязательными на соответствующих этапах внедрения.

## Постоянные данные

Подключите постоянные тома как минимум к каталогам:

- `/app/sessions` — сессии аккаунтов-сборщиков MAX;
- `/app/public/uploads` — загруженные изображения и файлы.

Без постоянного тома эти данные будут теряться после пересборки контейнера.

## Безопасный порядок выкладки

1. Создать резервную копию PostgreSQL.
2. Добавить переменные окружения и постоянные тома.
3. Убедиться, что домен имеет действующий TLS-сертификат и завершенную DNS-проверку.
4. Собрать новый контейнер и проверить healthcheck.
5. Проверить вход аккаунта по QR-коду и один ручной цикл парсера.

На этапе 0 структура базы данных не менялась, поэтому миграции выполнять не требуется. Начиная с этапа 1 изменения схемы будут применяться только через `prisma migrate deploy`, после резервной копии.
