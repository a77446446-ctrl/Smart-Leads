# Тематическая обработка: этап 2

23 сентября 2026 владелец разрешил точечное подключение тематической обработки после получения сообщений MAX. Разрешение не распространяется на авторизацию, Python worker, прокси, сессии, расписание и очистку купленных лидов.

## Реализовано

В `src/services/max-parser.ts` добавлены импорт, выбор обработчика перед обработкой пакета чата и вызов выбранного обработчика. Старый `processMessage` целиком сохранён. Без настройки `application_theme` используется прежний обработчик. Повреждённая настройка или ошибка её чтения останавливает выбор обработчика, а не незаметно включает другой режим.

При выбранной теме применяется `src/services/themed-message-processor.ts`:

- «Целевые» требуют совпадения с активной категорией: хотя бы один плюс и отсутствие минусов этой категории. При пересечении используется действующее ранжирование классификатора. ИИ не может заменить выбранную по словам рубрику.
- «Всё» сохраняет пользовательский текст независимо от совпадений и сбоя анализа. Совпавшая рубрика сохраняется, иначе используется «Другое». Пустые и служебные сообщения не публикуются.
- Новости, события и отдых, «Отдам даром» сохраняются как бесплатные публикации, допускающие отсутствие контакта. Ошибка анализа не блокирует совпавшую новость.
- Остальные темы используют модель контактов и прежнюю очередь доставки. Для целевых материалов остаются дополнительные проверки контакта, длины, даты и качества. В режиме «Всё» контакт не обязателен, как в прежнем режиме.
- ИИ используется для метаданных и дополнительных проверок платных целевых материалов. Текст бесплатной публикации сохраняется без обработки правилами вакансий.
- Повторный сбор не создаёт второй материал: используются прежние идентификатор сообщения, отпечаток содержимого и уникальные индексы. Уже сохранённые, включая купленные, материалы не переклассифицируются. Новые отказы по рубрикам не записываются навсегда: после исправления слов сообщение можно обработать заново, если оно ещё доступно в получаемой истории чата.

## Доступ и совместимость

Миграция `20260923010000_themed_publications` добавляет `Lead.accessMode` и `Lead.publicationTheme`. Все старые записи получают `CONTACT`; цена, статус, категория и покупки не меняются. Новые бесплатные записи получают `PUBLIC`, цену 0 и снимок темы. Смена темы сама по себе не открывает ранее закрытый материал. Нулевая цена не считается достаточным признаком бесплатной публикации.

API ленты показывает полный текст бесплатного материала. Карточка не требует покупки контакта и не показывает цену. Прямой запрос покупки такого материала возвращает `PUBLICATION_NOT_PURCHASABLE` до изменения баланса, статуса или покупок. Прежние контактные материалы сохраняют защиту.

Бесплатные публикации пока сохраняются только в веб-ленте: они не попадают в защищённую очередь платных MAX-анонсов с предложением забрать контакт. Отдельное оформление новостной доставки, все тематические подписи ленты и навигации относятся к этапу 3. Фотографии, видео и отдельный срок полного удаления относятся к этапу 4; действующая очистка сейчас не заменена.

## Проверка целостности

Исходный `docs/source-integrity.json` не перезаписывался. Одиннадцать файлов проверяются по прежним SHA-256. Для `max-parser.ts` проверка удаляет только три согласованные правки и сравнивает весь остаток с исходником коммита `de09017`, нормализуя переносы строк в LF. Изменения старого обработчика, авторизации и цикла получения приведут к отказу проверки. Правила точного исключения находятся в `scripts/protected-parser-extension.mjs`.

## Развёртывание и проверка

Перед запуском новой версии обязательна миграция базы через `prisma migrate deploy`; она уже входит в команду запуска проекта. Без неё новая версия API не должна запускаться. Откат приложения не требует удаления новых полей или бесплатных публикаций.

Проверки включают настоящее исполнение тематического обработчика с подменённой базой, API чтения и покупки, серверный рендер карточки и регрессии прежнего парсера. `node scripts/check-publication-migration.mjs` проверяет SQL на локальной PostgreSQL во временной таблице и откатывает транзакцию; действующие таблицы не изменяются. Проверка на живом MAX и полный приёмочный прогон в браузере пока не выполнялись.
