# Вход через Telegram

Smart Leads использует официальный Telegram OpenID Connect Authorization Code Flow с PKCE. Пароль, токен бота и секрет клиента не передаются в браузер. Сервер проверяет подпись ID token, `issuer`, `audience`, срок действия и одноразовый `nonce`.

## Настройка BotFather

1. Открыть `@BotFather` и выбрать Telegram-бота клиента.
2. Открыть **Login Widget**.
3. Добавить разрешённый origin: `https://ВАШ-ДОМЕН`.
4. Добавить точный callback: `https://ВАШ-ДОМЕН/api/auth/telegram/callback`.
5. Скопировать выданные **Client ID** и **Client Secret**. Токен бота для входа не используется.
6. В Advanced оставить алгоритм подписи `RS256`.

## Переменные Coolify

```dotenv
NEXT_PUBLIC_APP_URL=https://ВАШ-ДОМЕН
TELEGRAM_CLIENT_ID=ЧИСЛОВОЙ_CLIENT_ID_ИЗ_BOTFATHER
TELEGRAM_CLIENT_SECRET=СЕКРЕТ_ИЗ_BOTFATHER
ADMIN_TELEGRAM_IDS=ВАШ_TELEGRAM_ID
```

`TELEGRAM_CLIENT_SECRET` и `AUTH_SESSION_SECRET` должны быть секретными runtime-переменными. После сохранения переменных выполнить redeploy. Кнопка входа находится на `/login`.

Официальный OIDC Telegram требует заранее разрешённый публичный HTTPS-адрес. Полностью проверить реальный вход на `localhost` нельзя; локально проверяются интерфейс, криптография и обработчики, а авторизация ботом проверяется после деплоя домена.

## Модель пользователя

MAX ID хранится только у пользователей, которые действительно вошли через MAX. Telegram ID хранится в `ExternalIdentity`; фиктивные MAX ID не создаются. Уведомления существующего MAX-бота доступны только профилям с MAX ID. Таблица внешних идентификаторов позволяет позже добавить безопасную привязку Telegram к существующему профилю MAX без переноса покупок и баланса.

## После подтверждения Telegram открывается localhost:3000

Это ошибка перенаправления приложения за обратным прокси, а не штатный этап первой регистрации. Telegram может успешно подтвердить аккаунт, но приложение затем использует внутренний адрес контейнера для возврата в кабинет или на страницу ошибки.

Адрес callback и перенаправления при входе должны использовать единый публичный адрес из runtime-переменной NEXT_PUBLIC_APP_URL: HTTPS-домен без пути. Заголовки Host и X-Forwarded-Host не используются как источник доверенного адреса.

После доставки исправленного исходного кода в источник развёртывания выполните Redeploy клиентского приложения. Затем начните вход заново с публичного сайта; старую ссылку callback повторно открывать не нужно. Администратор возвращается на /admin, обычный пользователь — на /dashboard. При ошибке открывается /login?error=... на том же публичном домене. Если ошибка сохраняется, проверьте журнал с префиксом [TELEGRAM AUTH CALLBACK], не публикуя секреты и коды авторизации.
## Если VPS не достигает Telegram: отдельный HTTP/HTTPS-прокси

Задайте у клиентского приложения в Coolify переменную TELEGRAM_PROXY_URL:

```text
http://ЛОГИН:ПАРОЛЬ@АДРЕС:HTTP_ПОРТ
```

Используйте HTTP-порт провайдера, а не соседний SOCKS5-порт. Префикс https:// нужен только для прокси с поддержкой TLS-соединения до самого прокси. Специальные символы в логине и пароле (например @, : и %) должны быть URL-кодированы. Переменная секретная: **Runtime — включено, Build time — выключено, Value type — Single line**. Не добавляйте реальные реквизиты в Git.

После сохранения переменной и доставки обновлённого кода выполните **Redeploy**. Пустая переменная оставляет прямое соединение. Через заданный прокси идут только обмен кода Telegram на токен и загрузка публичных ключей Telegram. Проверка сертификатов и подписей сохраняется; автоматического перехода на прямое соединение при ошибке прокси нет. SOCKS5 в этой настройке не поддерживается.

Предварительная проверка из терминала VPS (Bash): команды выполняются по одной. Адрес вводится как http://АДРЕС:HTTP_ПОРТ без реквизитов, пароль вводится скрыто:

```bash
read -r -p 'Адрес HTTP-прокси: ' TG_PROXY
read -r -p 'Логин прокси: ' TG_PROXY_USER
read -r -s -p 'Пароль прокси: ' TG_PROXY_PASSWORD
printf '\n'
curl --noproxy '' --proxy "$TG_PROXY" --proxy-user "$TG_PROXY_USER:$TG_PROXY_PASSWORD" --connect-timeout 10 --max-time 25 -sS -o /dev/null -w 'HTTP %{http_code}\n' https://oauth.telegram.org/.well-known/jwks.json
unset TG_PROXY TG_PROXY_USER TG_PROXY_PASSWORD
```

Ожидается HTTP 200. Проверка не использует Client Secret Telegram. После Redeploy повторите вход с публичного сайта. Доступность конкретного платного прокси и реальная авторизация проверяются отдельно на сервере; локальные тесты их не подтверждают.
