# Smart Leads

Отдельная коммерческая версия на основе проверенного проекта. Рабочий каталог этой версии — `commercial`. Все команды ниже выполняются именно в нём.

## Состояние

Актуальная целевая модель продажи, самостоятельной настройки владельцем, демо и панели оператора описана в [плане коммерческого продукта](docs/commercial-product-plan.md). Документ отделяет реализованные функции от предстоящих этапов.

Выполнены сохранение исходной копии, выделение чистых исходников, аудит и первая часть нейтрального бренда. Добавлена страница `/admin/branding`: название, логотип, акцентный цвет, описание, приветствие страницы входа и email поддержки. Публичные данные бренда хранятся отдельно от токенов в `Setting.smart_leads_branding`.

Существующая MAX-авторизация, парсер и очередь MAX сохранены. Добавлен официальный вход Telegram по OIDC с PKCE и отдельными внешними идентификаторами пользователей; настройка описана в [инструкции Telegram](docs/telegram-login.md). Полноценный локальный кабинет работает с отдельной PostgreSQL на `127.0.0.1:55432`, тестовым администратором и учебными данными. Статическая страница `/demo` оставлена как презентационный экран. Структурированные медиа и мастер подключения будут реализованы следующими этапами. Подробности — в [аудите](docs/smart-leads-audit.md) и [плане пользователя](docs/implementation-plan.md).

## Начало работы

Для текущей Windows-среды portable PostgreSQL 16 установлен в `C:\SmartLeadsRuntime`. Рабочая база и сессии находятся там же и не входят в поставку.

Первоначальная подготовка локального кабинета:

1. Выполнить `npm run setup:local` — создаст кластер, `.env.local`, применит миграции и добавит учебные данные.
2. Выполнить `npm run demo` — запустит PostgreSQL при необходимости и приложение на порту 3100.
3. Открыть `http://localhost:3100/login`.
4. Нажать «Войти в рабочее приложение» для полноценной админки.

Повторные запуски требуют только `npm run demo`. Локальные ключи и добавленные позже параметры MAX/Telegram сохраняются при повторном выполнении `npm run setup:local`. Маршрут тестового входа выключен в production независимо от переменных окружения.

Для ручной остановки базы используется `npm run db:local:stop`. После перезагрузки компьютера команда `npm run demo` запустит её снова.

Для нового боевого экземпляра используются PostgreSQL и параметры из `.env.example`; локальный тестовый администратор и `.env.local` в поставку не включаются.

Полный перечень переменных и шагов для Coolify собран в [инструкции по развёртыванию](docs/coolify-deploy.md).

## Проверки

- `npm run test:branding` — проверки нового модуля.
- `npm run test:demo` — проверка безопасного локального демо-входа.
- `npm test` — полный набор, включая унаследованные проверки.
- `npm run typecheck` — типы.
- `npm run db:validate` — проверка Prisma-схемы.
- `npm run build` — production-сборка.
- `npm run verify:protected` — SHA-256 двенадцати защищённых файлов.
- `npm run verify:package` — отсутствие приватных файлов в поставке.

По [последнему отчёту проверки](docs/verification-2026-09-14.md) прежние два падения разобраны: 121/121 тестов прошли, исходное поведение парсера сохранено. Это результат предыдущего запуска, а не подтверждение готовности всех коммерческих функций. До продажи требуется полная приёмка на чистой установке с собственными ботами и проверка целевой среды Node.js 22.

## Поставка

Docker-контекстом должен быть каталог `commercial`, а не его родитель. `.dockerignore` исключает окружение, базы, сессии, резервные копии, загрузки и кэши. Зависимости устанавливаются заново; не передавать клиентам установленный `node_modules` и `.next`.

Домен, токены и ключи шифрования задаются отдельно для каждого экземпляра. В репозитории нет владельца по умолчанию, готовых сессий или скопированных пользовательских данных.
